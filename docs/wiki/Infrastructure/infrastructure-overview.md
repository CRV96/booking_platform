# Infrastructure Overview (`infrastructure/`)

Everything needed to **run** the platform — locally, in Docker, or in Kubernetes — lives under `infrastructure/`. This page maps the folder and explains *why* each piece is there. Deep dives: [Docker deployment](docker-deployment), [Kubernetes deployment](kubernetes-deployment), [Observability](observability).

```
infrastructure/
├── docker/          # Docker Compose stack + shared Dockerfile   → Docker deployment
├── k8s/             # Kubernetes manifests, Helm values, run.sh  → Kubernetes deployment
├── certs/           # mTLS certificate authority + per-service certs
├── keycloak/        # Realm JSON + branded email theme
├── nginx/           # Reverse proxy config (Docker)
├── prometheus/      # Metrics scrape config                      → Observability
├── grafana/         # Dashboards + datasource provisioning       → Observability
├── loki/            # Log store config                           → Observability
├── promtail/        # Log shipper config                         → Observability
├── init-scripts/    # kafka-init.sh (topic creation)
└── sonarqube/       # Local SonarQube analysis script + project config
```

## Why each piece exists

### `docker/` — the default way to run everything
A three-file Compose setup (`docker-compose.yaml` includes `startup.yaml` for infra and `services.yaml` for the apps) plus one **shared multi-stage `Dockerfile.service`** that builds any service from a `SERVICE_NAME` build-arg. This is the fastest path from clone to a running platform. See [Docker deployment](docker-deployment).

### `k8s/` — production-shaped deployment
Namespaced manifests, Helm values for the stateful infra (Postgres, Mongo, Redis, Kafka, Keycloak), per-service ConfigMap/Secret/Deployment/Service, an ingress, and a single `run.sh` that builds images, loads them, installs infra, and deploys in dependency order. See [Kubernetes deployment](kubernetes-deployment).

### `certs/` — mutual TLS for gRPC
A local certificate authority (`ca.crt`/`ca.key`) and a cert/key pair per service, generated by `generate-certs.sh`. `config/dev` defaults `GRPC_MTLS_ENABLED=true`, so **running services on the host requires generating these first**; Docker/K8s run plaintext inside their private networks. Why mTLS: it mutually authenticates services so only holders of a CA-signed cert can call a gRPC endpoint. The `.crt`/`.key` files here are throwaway local-dev certs — production uses real ones.

### `keycloak/` — identity bootstrap and branding
- `realm/booking-platform-realm.json` — the realm imported on first Keycloak start (`--import-realm`): clients, roles, user-profile attributes (including the billing-address attribute), SMTP, and the email theme.
- `themes/booking-platform/` — the branded FreeMarker email theme for verification emails. Edit templates and restart Keycloak — no rebuild.

### `nginx/` — the public edge (Docker only)
In Docker the [graphql-gateway](graphql-gateway) has **no published port**; nginx (port 80) is the only way in. It reverse-proxies `/` to the gateway and stamps the real client IP (`X-Forwarded-For`) so rate limiting can't be bypassed by spoofing. Not used for host or K8s runs (K8s uses an ingress).

### `prometheus/`, `grafana/`, `loki/`, `promtail/` — observability
Metrics (Prometheus scrapes each service's `/actuator/prometheus`), dashboards and datasources (Grafana, auto-provisioned), logs (Promtail ships service logs to Loki), and traces (Zipkin). Full detail and query examples: [Observability](observability).

### `init-scripts/` — Kafka topics
`kafka-init.sh` creates the required `events.*` topics (and their `-dlt` partners) so producers/consumers don't race to auto-create them.

### `sonarqube/` — local code quality
`run-sonar.sh` + `sonar-project.properties` run a local SonarQube analysis against the container in the Compose stack (mirrors the SonarCloud step in [CI/CD](ci-cd)).
